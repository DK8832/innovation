모집요강 요약

공식 공고문을 붙여넣으면 접수·시험·발표 날짜와 응시자격·시험과목·합격기준을 표준 항목으로 정리합니다. 날짜는 AI를 거치지 않고 원문에서 직접 추출하며, AI가 다듬은 서술형 항목도 원문 대조를 통과한 것만 표시합니다.

이틀 동안 두 번, 확신하던 전제가 실측 앞에서 뒤집혔습니다. 그 두 번이 이 서비스의 방향을 결정했습니다.

  1. 01

    문제 — 일정이 흩어져 있습니다

    국가기술자격은 큐넷, 컴퓨터활용능력은 대한상공회의소, 한국사는 국사편찬위원회, 토익은 YBM. 시험 하나를 준비하려면 사이트 네다섯 곳을 각각 들어가 접수 시작일과 마감일을 따로 확인해야 합니다. 하루만 놓쳐도 다음 회차까지 몇 달을 기다립니다.

    해결 방향은 세 갈래였습니다. 민간 애그리게이터, 공공데이터 연동, AI 자동화. 셋 다 결국 구현했지만 순서는 분명했습니다 — 수험생이 매일 여는 화면, 즉 통합 캘린더가 먼저입니다.

  2. 02

    먼저 만든 것 — 하나의 캘린더

    서로 다른 5개 주관처의 9개 종목을 한 화면에 모았습니다. 접수 시작·마감·시험일·발표일을 각각의 사건으로 펼쳐 캘린더와 임박순 리스트로 보여주고, 마감까지 남은 일수를 색으로 구분했습니다.

    여기서 첫 원칙이 생겼습니다. 확인하지 못한 날짜는 채우지 않습니다. 상시로 운영돼 애초에 고정 날짜가 없는 시험은 캘린더에서 빼고 별도 구역에 뒀습니다. 빈칸을 그럴듯한 숫자로 메우는 순간 이 서비스는 없느니만 못해집니다.

  3. 03

    첫 번째 반전 — 크롤링이 안 됩니다

    다음 계획은 흔한 방식이었습니다. 주관처 사이트를 주기적으로 긁어 일정을 자동 갱신한다. 코드를 쓰기 전에 대상 사이트를 직접 두드려봤습니다.

    가설

    수십 개 주관처 사이트를 크롤링해 일정을 자동으로 모은다

    대상실측 결과판정
    큐넷 200 OK, 235KB 수신. 그런데 본문에 날짜가 없고 viewStr += "<td>…" 형태로 자바스크립트가 표를 조립 불가
    한국사 200 OK지만 본문 3.6KB. 내용은 “허용되지 않는 요청입니다” — 봇 차단 불가
    공공데이터포털 403 SERVICE_KEY_IS_NOT_REGISTERED_ERROR — 엔드포인트에는 닿았고 키만 없다는 뜻 채택
    실측 →

    크롤러는 만들 수는 있었습니다. 다만 매번 빈 값을 가져오면서 아무 오류도 내지 않았을 겁니다. 날짜가 틀리면 사용자가 시험을 통째로 놓치는 서비스에서, 조용히 실패하는 수집기는 없는 것보다 나쁩니다.

    그래서 크롤링을 주 경로에서 내리고 공공데이터포털 국가자격 시험일정 API를 1순위로 올렸습니다. 기능을 줄인 게 아니라 더 정확한 출처로 갈아탄 것입니다.

  4. 04

    수집한 값을 자동으로 반영하지 않기로 했습니다

    자동 동기화를 붙이면서 가장 오래 고민한 지점입니다. 결론은 수집한 날짜를 서비스 데이터에 자동으로 덮어쓰지 않는 것이었습니다. 달라진 값만 찾아 검토 큐에 쌓고, 사람이 확인한 뒤에 반영합니다.

    종목 이름을 잇는 규칙도 일부러 깐깐하게 뒀습니다. 후보가 둘 이상이면 아예 연결하지 않습니다. “전기기사”와 “전기공사기사”처럼 비슷한 이름에 남의 날짜가 붙는 것보다 차라리 못 찾는 편이 낫기 때문입니다.

  5. 05

    AI에게 무엇을 시키지 않을 것인가

    모집요강 원문을 정리해주는 기능(요강 요약 탭)을 만들면서, 핵심은 AI에게 시킬 일이 아니라 시키지 않을 일을 정하는 데 있었습니다.

    • 날짜는 정규식으로만 뽑습니다 생성 모델에는 날짜를 요청하지도, 받지도 않습니다. 접수 마감일 하나가 틀리면 사용자의 1년이 날아가는데, 그럴듯한 날짜를 지어내는 것은 이 모델들의 확실한 실패 유형입니다.
    • 규칙 기반이 기본이고, AI는 선택적 강화입니다 API 키가 없는 사람도 기능을 그대로 쓸 수 있어야 합니다. AI는 응시자격·시험과목 같은 서술형 항목만 다듬습니다.
    • AI가 낸 값도 원문 대조를 통과해야 채택합니다 추출한 문장의 의미 단어 중 70% 미만만 원문에 있으면 지어낸 것으로 보고 버립니다. 버린 항목은 화면에 그 사실을 그대로 표시합니다.
    입력원문 근거 비율결과
    원문에 있는 내용1.00채택
    절반만 진짜0.33폐기
    완전히 지어낸 내용0.00폐기
  6. 06

    두 번째 반전 — 검사 도구가 서버를 멈추고 있었습니다

    기능이 다 붙은 뒤 안정화를 위해 동시 부하를 걸었습니다. 서버가 죽는 것처럼 보였습니다. 요청이 하나둘 타임아웃되더니 결국 연결 자체가 거부됐습니다.

    가설

    동시 요청이 몰리면 서버가 버티지 못하고 죽는다 

    동시 구독 30건    →  8건 타임아웃
혼합 읽기 216건   →  216건 전부 실패
상태 확인         →  응답 없음
요약 10건         →  WinError 10061 연결 거부

    로그를 뜯어보니 서버 쪽에는 오류가 한 줄도 없었습니다. 죽은 게 아니라 멈춰 있었습니다. 원인은 서버가 아니라 그것을 시험하던 코드였습니다 — 서버를 파이프로 띄워놓고 그 출력을 아무도 읽지 않았습니다. 접속 로그가 파이프 버퍼를 채우는 순간, 서버는 로그를 쓰다가 그 자리에 멈춰 섭니다.

    실측 →

    출력을 파일로 받도록 한 줄 바꾸자 같은 부하가 그대로 통과했습니다. 동시 구독 30건, 혼합 읽기 216건, 오류 0건.

    여기서 끝냈으면 시험 도구 하나 고친 일로 남았을 겁니다. 그런데 저장소에 들어있는 검증 스크립트가 똑같은 패턴을 쓰고 있었습니다. 지금까지 통과한 건 요청 수가 적어서였을 뿐입니다. 같이 고쳤습니다.

  7. 07

    초록불을 믿지 않는 방법

    검사가 통과했다는 사실 자체는 근거가 되지 못합니다. 아무것도 보고 있지 않은 검사도 똑같이 초록불을 켭니다. 그래서 새 검사를 만들 때마다 지켜야 할 동작을 일부러 망가뜨려 빨간불을 먼저 확인했습니다.

    일부러 넣은 결함잡혔는가
    남은 일수 계산에 +1잡힘
    데이터에서 필수 항목 삭제잡힘
    종목 이름 매칭을 느슨하게잡힘
    날짜 종류를 가까운 라벨이 아니라 첫 라벨로잡힘
    원문 대조를 건너뛰게잡힘
    서버 출력을 다시 파이프로잡힘 · 86건 타임아웃
    111 → 162 → 166 검사 항목 · 전부 통과

    그 밖에 실제로 잡힌 것들. 모달 뒷배경이 숨겨진 상태에서도 화면 전체를 덮어 클릭을 가로챘고, 설정 파일에 한글 주석을 넣었더니 설치 도구가 인코딩을 잘못 읽어 깨졌습니다. 모두 브라우저와 새 폴더에서 직접 눌러보다 발견했습니다.

아직 못 한 것

확인하지 못한 것을 확인한 것처럼 적지 않는 편이, 이 프로젝트에서 지킨 원칙과 맞습니다.

  • 공공 API의 실제 응답을 눈으로 보지 못했습니다. 발급 키가 없어 공식 문서 기준으로 구현했고, 종목명 필드는 표기가 문서마다 달라 후보를 순서대로 시도하도록 방어적으로 짰습니다. 파이프라인 자체는 문서 그대로의 가짜 응답을 넣어 검증했습니다.
  • 시험이 9종목뿐입니다. 공공 API 동기화로 국가기술자격은 넓힐 수 있지만 종목마다 검토를 거쳐야 해서 아직 반영하지 않았습니다.
  • 토익·오픽 같은 민간 시험은 공식 API가 없습니다. 지금은 직접 확인해 정리한 데이터에 의존하고, 공지가 바뀌면 수동으로 갱신해야 합니다.
  • 검토 큐는 아직 보기만 됩니다. 승인·반려 화면이 없어 확인 후에는 데이터 파일을 직접 고칩니다.
